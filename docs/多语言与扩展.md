# 多语言与扩展

这套工具的主线是**中日互译**，但底层已经按"语言无关"设计，加一门语言不需要改代码。
本文说明：现在支持什么、预留了什么、以及**刻意没做什么**。

---

## 一、现在已经支持

| 能力 | 说明 |
|---|---|
| **任意语言对** | 作品自带 `lang: {src, tgt}` 声明，不写死中日 |
| **语言注册表** | `assets/languages.json` 描述显示名、方向、字体、默认标注类型；UI 按钮文字由它生成 |
| **视图抽象** | 按钮表示"看哪一侧"（`side/stack/src/tgt`），不表示"哪种语言" |
| **字段语义化** | 数据字段是 `src / src_annotated / tgt / notes`，不含语言名 |
| **标注可插拔** | 日语用 `ruby`，英语等无注音语言用 `none`；校验按标注类型分派 |
| **读音表** | 专名读音一次定稿、全书强制、可机械校验 |

内置注册表：`ja`、`zh-Hans`、`zh-Hant`、`en`、`ko`。

## 二、加一门新 LTR 语言（例如日译英）

```powershell
# 1) 作品声明语言
py -3.11 tools\init_work.py --work-id my-novel --title "My Novel" --src-lang ja --tgt-lang en

# 2) 若注册表里没有这门语言，在 assets/languages.json 加一条
#    { "en": { "name":"English","label":"英文","dir":"ltr","annotation":"none","font":"Georgia,serif" } }
```

就这两步。UI 按钮会自动显示「日文 / 英文」，字体按注册表切换。

**如果新语言没有现成条目**：`schema.lang_info()` 会退回 `{name: code, dir: 'ltr', annotation: 'none'}`，
工具仍能跑，只是字体用继承值——补一条注册表记录即可。

## 三、标注类型（注音 / 转写）

校验的通用形式是：

```
reduce(annotated, 标注类型) == 原文
```

| 类型 | 适用 | 还原方式 | 状态 |
|---|---|---|---|
| `ruby` | 日文振り仮名、中文拼音 | 去 `<rt>`、去标签 | ✅ 已实现 |
| `none` | 英语等无需注音 | 恒等 | ✅ 已实现 |
| `insert` | 阿拉伯语元音符号（字符插进词里） | 删标注字符集 | ⛔ 预留，调用即报错 |
| `paren` | 括号式转写 `東京(とうきょう)` | 删括号内容 | ⛔ 预留，调用即报错 |

**为什么其他类型只是"预留"而不是"支持"**：它们的还原规则不是剥标签，需要为每种语言
精确定义"哪些字符是标注"。没有定义就假装支持，只会让校验失效——而校验失效意味着
**原文可能被悄悄改写**。所以留好接缝（`schema.ANNOTATIONS`），但不假装能跑。

> 底线不变：无论哪种标注，**还原后必须逐字等于原文**。

## 四、刻意没预留的三件事

| 不做 | 原因 |
|---|---|
| **RTL 布局**（阿拉伯语/希伯来语） | 半吊子的 RTL 比不支持更糟：侧栏要镜像、对照顺序要按方向决定、混排标点会错乱，是一次独立的 CSS 重构。现在只在 DOM 上标注了 `dir` 属性，样式仍按 LTR 渲染。**真要做时单独立项。** |
| **同一本书多个译本共存** | 会让 `work.json` 从"一源一译"变成"译文分桶"，复杂度陡增。真需要时的升级路径很清晰：拆成两个 work（同源、不同 `tgt`）。 |
| **标注器插件系统**（动态加载） | 目前只有两种实现，做插件机制是纯粹的过度设计。有了 `ANNOTATIONS` 分派就够了。 |

## 五、字段对照（迁移参考）

| 旧名（中日专用） | 新名（语言无关） |
|---|---|
| `paragraphs[].ja` | `src` |
| `paragraphs[].ja_ruby_html` | `src_annotated` |
| `paragraphs[].zh` | `tgt` |
| `paragraphs[].ruby_notes` | `notes` |
| `chapters[].title_ja` | `title_src` |
| `chapters[].title_zh` | `title_tgt` |

**旧作品不必急着迁移**：读取时旧名自动兼容（`schema.get_field`），
阅读器也在 `prepareWork` 里做了一次字段归一。想迁移就跑：

```powershell
py -3.11 tools\migrate_work.py --source <旧 work.json> --work-id my-novel
```

迁移是幂等的，会自动补上语言声明。

## 六、数据流中的语言相关部分

```
library/<work_id>/
  source.txt         原文（任意语言）
  glossary.json      术语表：源语言词 → 目标语言词
  readings.json      读音表：专名 → 指定读音（源语言专有，与目标语言无关）
  work.json          含 lang 声明与语义化字段
  prompts/…          （仓库级）提示词，可自由修改
```

- **术语表**与语言对绑定（换目标语言要重配）
- **读音表**只与源语言有关（日译中、日译英共用同一份读音表）
- **提示词**在仓库的 `prompts/translate.md`，改它不需要动代码，
  见 [提示词修改指南](提示词修改指南.md)
