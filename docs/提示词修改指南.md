# 提示词修改指南

给下载这套工具的人：**想调整翻译风格或注音策略，改 `prompts/translate.md` 就够了，不用碰 Python。**

---

## 提示词在哪里

```
prompts/translate.md      ← 唯一的提示词文件，纯文本，直接编辑
```

改完保存，下次运行 `api_pipeline.py` 立即生效。不需要重启、不需要编译。

如果这个文件被删掉，程序会退回用内置的简版模板——但**请优先改文件**，内置的只是兜底。

---

## 文件结构

提示词由四块组成，从上到下：

| 块 | 作用 | 改动风险 |
|---|---|---|
| **角色设定** | 告诉模型"你是谁" | 低，随意改 |
| **输出格式** | 规定每行输出哪几个字段 | ⚠️ **高，别改字段名** |
| **硬性要求** | 不可篡改原文、注音全覆盖等底线 | ⚠️ 高，建议只增不减 |
| **术语表 / 读音表占位符** | 由程序填入你的 `glossary.json` / `readings.json` | ⚠️ 不能删 |

---

## 两个占位符（必须保留）

```
[[glossary]]    → 程序替换成 glossary.json 的内容（术语表）
[[readings]]    → 程序替换成 readings.json 的内容（读音表）
```

写错了会变成字面量 `[[glossary]]` 发给模型——模型看得懂，但你的术语表就白配了。

**验证方法**：改完跑一次，看是否有报错；更稳妥的是直接在终端确认渲染结果：

```powershell
py -3.11 -c "import sys;sys.path.insert(0,'tools');import api_pipeline as a;print(a.render_prompt('你的work-id',{}))"
```

这会打印最终发给模型的完整提示词。

---

## 三个字段名不能改

模型必须按固定字段名回话，程序才能解析：

```json
{"id":"...","tgt":"译文","src_annotated":"带标注的原文","notes":""}
```

| 字段 | 含义 | 改了会怎样 |
|---|---|---|
| `id` | 段落编号 | 校验时对不上号，整批判不合格 |
| `tgt` | 目标语言译文 | 译文无法回填 |
| `src_annotated` | 带注音/转写的原文 | 无法校验原文有没有被篡改 |
| `notes` | 读音存疑记录 | 丢失存疑标记（不致命） |

## 常见改法

### 1. 调整译文风格

找到「译文」那一条，改措辞即可。例如：

```
4. 译文：通顺自然的简体中文小说文风，准确传达原意，保留人物语气与「」引号。
```

改成更文学化的：

```
4. 译文：简体中文，文学性强，句式可适度调整以求流畅；保留「」引号与人物语气；
   避免翻译腔（不要出现"作为……的存在"这类表达）。
```

### 2. 改称呼/敬语处理

日文敬语翻成中文很难，值得专门写一条：

```
5. 称呼：さん→「先生/小姐」视关系定；君→「你」；様→「大人」；
   同一人物在全书中的称呼保持一致。
```

### 3. 放宽或收紧注音

比如你发现模型在很常见的词上也注音、显得啰嗦：

```
- 以下常见词可以不注音（读者默认会读）：今日、明日、一人、二人
```

反之，若想更彻底：

```
- 人名、地名即使全是假名，也要在首次出现时用 notes 标注读音
```

### 4. 增加内容约束

例如不希望译文出现某些表达：

```
- 不使用网络流行语；不添加原文没有的心理描写。
```

### 5. 换语言对（如日译英）

把角色设定与译文要求改成对应语言即可，**字段名保持不变**：

```
You are a literary translator working from Japanese into English.
...
4. Target text: natural literary English, keep the 「」 quotes as “”.
```

同时在作品目录的 `work.json` 里把 `lang` 改成 `{"src":"ja","tgt":"en",...}`
（或在 `init_work.py` 时用 `--tgt-lang en`）。

## 改坏了怎么办

**症状**：跑 `api_pipeline.py` 后发现大量批次被判不合格、反复重试。

**原因**通常是这三类：

| 症状 | 原因 | 修法 |
|---|---|---|
| 提示 `id 序列不符` | 格式块被改坏，模型输出的字段名变了 | 恢复输出格式那一段 |
| 提示 `改动了日文原文` | 硬性要求里"不得改写"被删或弱化 | 把第 2 条加回去 |
| 提示 `汉字未全部注音` | 注音要求被弱化 | 把「100% 覆盖」那条加回去 |

**兜底**：删掉 `prompts/translate.md`，程序会用内置简版模板继续工作；你也可以从 git 恢复：

```powershell
git checkout prompts/translate.md
```

---

## 建议的改动方式

1. **一次只改一处**，跑一个小批（`--units 1`）看效果，别一次改五条
2. **改动留痕**：这个文件在 git 里，commit 时写清楚"为什么改"
3. **别删占位符**，也别改字段名
4. 校验是机械的、不看你的措辞——所以放宽措辞不会让校验失效，
   但如果模型因此开始改写原文或漏注音，校验会**立刻拦下并自动重试**，
   表现为跑得慢、日志里出现重试记录

> 换句话说：**你可以放心改文风**（模型行为变了，但底线由校验守住）；
> **不要试图改底线**（改那些标准只会让产出被拒收）。
